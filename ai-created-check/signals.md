# AI-Created Signals Catalog

Patterns are case-insensitive starting points. Exclude `node_modules`, `vendor`, `.venv`, `dist`, `build`, lockfiles (`package-lock.json`, `yarn.lock`, `poetry.lock`, `Cargo.lock`, etc.; `requirements.txt` is not a lockfile), and codegen output. Always read the match in context before recording it.

File searches below use `grep -rniE ... .`. In a git repo, use `git grep -I -niE '<pattern>'` instead so `.git` and untracked noise are skipped; otherwise add `--exclude-dir=.git`. In zsh, quote arguments containing `=`.

## Hard signals (can confirm)

### H1 - Commit trailers and messages

```bash
git log --all -i -E --grep='co-authored-by:.*(claude|anthropic|copilot|cursor|codex|openai|chatgpt|gemini|aider|devin|windsurf|codeium|cline|amazon q|tabnine|jules)' --format='%h %ad %s' --date=short
git log --all -i -E --grep='generated (with|by) .*(claude|copilot|chatgpt|cursor|codex|gemini|ai)|🤖 generated|aider:' --format='%h %ad %s' --date=short
```

Known markers: `Co-Authored-By: Claude ... <noreply@anthropic.com>`, `🤖 Generated with [Claude Code]`, `Co-authored-by: Copilot`, `Co-authored-by: Cursor Agent`, aider commit prefix `aider:`, `Generated by Codex`.

### H2 - Bot or AI-tool authors/committers

```bash
git log --all --format='%h %an <%ae> | %cn <%ce>' | grep -iE 'claude|anthropic|copilot|cursor|codex|openai|devin|aider|gemini|jules|sweep|codegen|\[bot\]'
```

AI agents: `copilot-swe-agent[bot]`, `Copilot`, `devin-ai-integration[bot]`, `claude[bot]`, `cursor[bot]`, `chatgpt-codex-connector[bot]`, `google-labs-jules[bot]`, `sweep-ai[bot]`. Ignore non-AI bots (`dependabot`, `renovate`, `github-actions`) — list them nowhere.

### H3 - AI branch names

```bash
git branch -a --format='%(refname:short)' | grep -iE '(^|/)(claude|copilot|codex|cursor|devin|aider|jules)[/-]'
```

Files changed by commits unique to those branches are Confirmed:

```bash
git log --format=%h <ai-branch> --not <default-branch>   # if already merged, use the merge commit's second parent range: git log <merge>^1..<merge>^2
git show --name-only --format= <sha>
```

### H4 - Generator headers in files

```bash
grep -rniE 'generated (by|with|using) (claude|chatgpt|gpt-?[0-9]|copilot|cursor|codex|gemini|an? ai|ai assistant|llm)|written by (claude|chatgpt|ai)|ai[- ]generated' .
```

### H5 - Chat leftovers in files

Text a model writes to the user that was pasted into the file:

```bash
grep -rniE "as an ai (language )?model|i (can't|cannot) (browse|access)|here('s| is) (the|an?) (updated|complete|full|revised|refactored) (code|version|file|implementation)|certainly!|i hope this helps|let me know if you (need|have|want)|\.\.\. ?(rest of|existing|previous) (the )?(code|file|implementation)( remains| unchanged)?|// \.\.\. existing code|# \.\.\. existing code|<\|im_start\|>|\[insert .* here\]" .
```

Also: markdown code fences (```` ``` ````) inside non-markdown source files, and "Explanation:" / "Key changes:" blocks after code.

## Soft signals (raise likelihood only)

Record a soft signal only with a concrete example quoted from the file.

### S1 - Comment style
- Comments that restate the next line (`// Increment counter` above `i++`) across a whole file.
- Numbered step comments (`# Step 1: ...`, `// 2. Validate input`) in non-tutorial code.
- Emoji in code comments, log lines, or CLI output (`✅`, `🚀`, `❌`) where the rest of the repo has none.
- Uniform docstrings on every function, including trivial getters, unlike neighboring files.

### S2 - Prose and docs style
- Docs/READMEs with emoji section headers, "Key Features" / "Overview" / "Conclusion" scaffolding, heavy bold on bullet leads, frequent em dashes.
- Phrases: "comprehensive", "robust", "seamless", "leverage", "delve", "it's worth noting", "in summary".

### S3 - Placeholder and hallucination artifacts
- `TODO: implement actual logic`, `// Replace with your actual ...`, `your-api-key-here`, mock data left in production paths.
- Imports or API calls that do not exist in declared dependencies or the library's real API.

### S4 - Style mismatch with the repo
- File differs sharply from sibling files: naming convention, error-handling density (try/except around everything), defensive checks, type annotations, formatting.
- Very generic names (`data`, `result`, `helper`, `processData`, `handleSubmit`) throughout one file but not elsewhere.

### S5 - History shape

Commit-level: counts as one soft signal for each file changed in the flagged commit.
- One commit adds many complete, polished files at once with no follow-up fixes.
- Commit messages switch abruptly to a uniform, verbose conventional-commit style with bullet-list bodies.
- Bursts of large commits minutes apart.


Presence shows AI tools are configured for this repo. It does not show which files they touched. Note the tools and the date each config file was first committed (`git log --diff-filter=A --format=%ad --date=short -- <file>`): mention it for files changed after that date, but R1 does not count toward the Likely threshold and never makes a file Confirmed.
